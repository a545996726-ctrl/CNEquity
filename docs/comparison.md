# 选型：什么时候需要 CNEquity

CNEquity 适合持续积累、反复查询和复查历史口径的数据工作。选择时先判断你需要一次取数、长期数据层，还是研究与交易应用。

## 按工作方式选择

| 需求 | 合适的工作方式 | CNEquity 在其中的位置 |
|---|---|---|
| 偶尔取一个报价或一张表 | 直接使用所需来源的 API 或取数库 | 建湖成本可能超过收益 |
| 同一份历史数据反复用于多个研究 | 本地持久存储、增量采集、版本与质量检查 | 这是项目的主要用途 |
| 获取有明确授权或服务承诺的数据 | 按供应商合同选择数据服务 | 公共来源采集不能替代授权或 SLA |
| 做模型训练、回测或交易执行 | 使用相应研究 / 交易框架 | 湖可作为其输入；集成与策略逻辑由下游负责 |
| 让 agent 查询历史数据 | 先准备数据与证据，再暴露只读工具 | `cne mcp` 提供本地 stdio 工具 |

AkShare、efinance、Tushare、Baostock、Qlib、vn.py 等名字常出现在这些工作流中；这里不对它们的当前功能、价格或授权做静态评分。选择时以相应项目和服务的实际接口、版本与条款为准。

## CNEquity 已负责什么

- 统一数据集、主键、单位与来源列，落地为开放 Parquet。
- 按批次采集、维护水位、保留失败范围并支持续跑。
- 对候选数据和已发布数据分别提供质量检查，发布新 revision 保留修订证据。
- 提供复权、历史股票池与 PIT 查询语义；严格模式显式暴露缺口。
- 提供 Python / SQL、控制台和 MCP 入口。

## 使用成本与边界

需要自己承担磁盘、运行调度和上游可达性。快照数据只能从启用后积累；历史回填不自动具备严格 PIT 证据。版本保留有上限，长期重现需保存快照、依赖与软件版本。

项目不提供托管行情、回测引擎、交易信号或下单。代码许可不授予上游数据再分发权，见[数据许可](legal-and-data-sources.md)。
